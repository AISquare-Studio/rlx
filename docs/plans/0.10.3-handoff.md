# rlx 0.10.3: handoff ("rlx for apps")

This branch, `rc/0.10.3`, is the release train for **rlx for apps**. It starts from `main` at v0.10.1 (c6b523c3).

**It runs in parallel with 0.10.2.** A separate manager, in a separate checkout, runs 0.10.3 while 0.10.2's train (`rc/0.10.2`, PR #545) is still open. **Once 0.10.2 has landed on `main`, that manager merges `main` into `rc/0.10.3`**, and only then starts the items tagged `needs 0.10.2`.

rlxapp's manager wrote this file at the owner's request, following the owner's decisions (2026-11-25). rlxapp is the desktop app for people who don't use a terminal (AISquare-Studio/rlxapp). It builds against an `Engine` interface, defined in rlxapp's `docs/architecture.md` (rlxapp PR #1). This revision is traced against that PR's head 760e5fd. Until this train ships, the app runs on a fake engine. Section 8 maps each `Engine` call to the contract item here that serves it.

## What 0.10.3 ships

- **rlxd, the engine.** A long-running local daemon written in Rust. It replaces tmux as the process host and lives in this repo as a Cargo workspace (`rlxd/`). It has its own CI on three OSes, and its binaries ship with rlx releases. Python stays the orchestration brain and the TUI.
- **What the app needs, on rlxd:**
  - a tmux-free headless runner that turns Claude Code's stream-json output into structured events;
  - native Windows;
  - a user-defined scheduler, whose app-owned jobs fire only while the app is running;
  - a connector surface;
  - a home for non-developers that is not a project folder, with an erase.
- **Asks A–D:** a versioned JSON envelope, a silent installer, a local event stream, and native Windows for install, accounts, upgrade and doctor.
- **What the ask-E answers require (ask K):** non-UI rlx processes, rlxd included, that the upgrade counts and can stop and restart, and Keychain variables passed through.
- **Asks F–J:**
  - F: the app's gate decides every tool call, through a PreToolUse hook backed by host permission prompts, and fails closed;
  - G: sign-in without a TTY;
  - H: connector listing with read/write hints, and one read call with no model turn;
  - I: the run lifecycle: run IDs as session IDs, run listing, attach from a sequence number, a durable record of every gated call, cancel and a protocol handshake;
  - J: runs name their connectors, and no turn starts until they are connected.
- **The app contract:**
  - every command the app calls;
  - one JSON envelope with `schema_version`, and a `hello` handshake;
  - the event stream, with data shapes for every topic;
  - runner, scheduler and connector events;
  - install, upgrade and sign-in as JSON lines.
- **Engineering:** `services/fleet.py` (19,686 lines) is split into cohesive modules, followed by a DRY pass across services and tests.

## The owner's decisions (2026-11-25)

1. **rlx powers both of rlxapp's modes from day one**, simple and developer. The app never drives Claude Code directly. Every agent run, widget refresh and connector call goes through rlx. The earlier proposal is rejected: simple mode driving `claude -p` from the app, with rlx only in developer mode.
2. **The engine is rlxd, written in Rust. This is the plan.**
   - **What it is:** a long-running local daemon that replaces tmux as the process host.
   - **What it hosts:** PTYs through `portable-pty` (ConPTY on Windows), and headless Claude Code sessions that emit structured stream-json events.
   - **Hooks:** it receives Claude Code hooks over a local socket through a tiny client, so no Python process starts for each hook.
   - **Scheduler:** it runs the user's scheduler.
   - **Clients:** it pushes events to the TUI, rlxapp and Remote.
   - **Platforms:** it is native on Windows.
   - **Where it lives:** in this repo as a Cargo workspace (`rlxd/`), with a client crate that rlxapp depends on. It has its own CI on three OSes, and its binaries ship with rlx releases.
   - **Python's role:** it stays the orchestration brain and the TUI.
3. **The rest of what the app needs** is in 0.10.3: a tmux-free headless runner, native Windows, a user-defined scheduler, a connector surface, a non-project home, and rlxapp's asks A–D.
4. **Ask E was answered from the code**, with no release. Section 4 says what those answers require of rlx.
5. **`services/fleet.py` is split** into cohesive modules, with a DRY/dedup pass across services and tests (section 6).
6. **Every item below is tagged** `independent` or `needs 0.10.2: <which 0.10.2 work>`.
   - rlxd is independent.
   - The fleet.py split needs 0.10.2 to have landed, because 0.10.2's coders are editing fleet.py now.
7. **0.10.3 runs in parallel with 0.10.2**, under its own manager in its own checkout, and merges `main` in once 0.10.2 has landed (above).
8. **App-owned jobs need the app** (rlxapp's design call, 2026-11-25). Closing rlxapp's window keeps it running in the menu bar or tray. App-owned scheduled jobs fire only while an app gate client is connected, and "app absent" means the user quit the app (2.3).

## How to read the checks

Every item ends with an **Accept** check: commands, plus the exit code or output shape they must produce. Every check must be able to fail. A check that can pass on an empty stream, a missing field or a skipped step is a bug in this file.

**Clients.**
- **`AISQUARE_HOME`** points at a fresh temporary home for each check, so no check touches a real home. `CLAUDE_CONFIG_DIR` points at a fresh folder inside it.
- **`rlxd call [--as-app] <method> [<params-json>]`** sends one request on a new connection and prints the response envelope (7.2). Exit codes: 0 when `ok`, 1 when not `ok`, 3 when rlxd isn't running.
- **`rlxd events [--as-app] [--topics a,b] [--since SEQ] [--follow] [--until TYPE[,TYPE…]] [--limit N] [--timeout S]`** prints event envelopes (7.3) as JSON lines. It exits 0 once one of `--until`'s types is seen, 4 on timeout and 3 when rlxd isn't running.
- **`--as-app`** makes the client say `hello {role: "app"}`, as rlxapp does. An app-role connection is the gate (5.1).

**The fake Claude Code.**
- **`RLXD_CLAUDE_BIN=rlxd/tests/fixtures/fake-claude/<scenario>`** makes rlxd run a stand-in for `claude`. It replays recorded stream-json, in the shape rlxapp's architecture recorded (§4 and §18, E6, E9 and E11). Every check therefore runs in CI on three OSes with no model turn.
- **The fixture log.** Each scenario writes `$AISQUARE_HOME/fake-claude.log.json`. Times are milliseconds since that start's spawn:

  ```json
  {"starts": [{"argv": ["…"], "env": {"CLAUDE_CONFIG_DIR": "…"},
               "stdin": [{"at": 812, "type": "user"}], "stdin_eof_at": null,
               "connected_at": 640, "delivered": true,
               "hook_replies": [{"hookSpecificOutput": {"permissionDecision": "deny", "permissionDecisionReason": "…"}}],
               "tool_ran": false, "exit": 0}]}
  ```

  - `starts` has one entry per process start.
  - `delivered` says whether that start's output reached clients.
  - A check on a single-start run reads `.starts[-1]`.
  - A check compares a time only after checking that it is a `number`.

**Two helpers** used by the run checks. `gated_start` connects an app-role client before the run starts, so the gate is reachable, and captures the run's events into `ev.jsonl`:

```sh
gated_start() {  # $1 = run.start params (JSON, without run_id); sets s, r and the capture's pid
  s=$(rlxd call status | jq .data.seq); r=$(uuidgen | tr 'A-Z' 'a-z')
  rlxd events --as-app --topics run,needs_you --since "$s" --follow \
    --until run.done,run.failed,run.needs_you --timeout "${T:-60}" > ev.jsonl & cap=$!
  for i in $(seq 25); do rlxd call status | jq -e '.data.clients.app >= 1' >/dev/null && break; sleep 0.2; done
  rlxd call run.start "$(jq -c --arg r "$r" '. + {run_id: $r}' <<<"$1")" >/dev/null
}
decide() {  # $1 = allow | deny | draft, $2 = reason; answers the run's first run.tool_call
  c=$(rlxd events --topics run --since "$s" --follow --until run.tool_call --timeout 30 \
      | jq -r --arg r "$r" 'select(.type == "run.tool_call" and .data.run_id == $r) | .data.call_id' | head -1)
  test -n "$c" && rlxd call --as-app run.decide "{\"run_id\":\"$r\",\"call_id\":\"$c\",\"decision\":\"$1\",\"reason\":\"$2\"}"
}
```

**Where checks run.**
- **Pre-release and release forms.** A check marked **(release)** needs a published release. Each such check has a pre-release form that CI runs on any head. It uses:
  - a wheel of the tree (`uv build --wheel`, as install.yml does through `AISQUARE_INSTALL_PACKAGE`);
  - rlxd built from the tree (`cargo build --release --manifest-path rlxd/Cargo.toml`);
  - a stub releases server, named by `AISQUARE_RELEASES_URL`, that serves those archives and records each requested path in `stub-requests.log`.

  `V=$(rlx --version | awk '{print $2}')` is the tree's version. No pre-release check compares against a version literal.
- **`[real]`** marks a check that needs a real Claude Code signed in with claude.ai. An API key changes what loads, so it doesn't count.
  - These checks run by hand on such a machine, and the sub-PR records their output.
  - `[real, connectors]` also needs a claude.ai Slack connector.
  - Whether a nightly leg gets such a login is an owner step.
- **Windows forms.**
  - `kill -9 $p` is `Stop-Process -Force -Id $p`.
  - `sh -c 'exit 3'` is `cmd /c exit 3`.
  - `pgrep -f X` is `Get-CimInstance Win32_Process | Where-Object CommandLine -like '*X*'`.
  - `uuidgen` is `[guid]::NewGuid()`.
- **Schemas** live in `rlxd/schemas/v1/`. `uvx check-jsonschema --schemafile <schema> <file>` validates against them.

## 1. rlxd: the engine

```
rlxd/                    Cargo workspace (this repo)
  crates/rlxd-proto/     wire types, protocol_version, JSON Schemas (schemars); no I/O
  crates/rlxd-client/    the client crate rlxapp depends on: connect, hello, call, subscribe, attach
  crates/rlxd/           the daemon: PTY host, runner, gate, scheduler, hook intake, event bus
  crates/rlxd-hook/      the tiny hook client
  schemas/v1/            generated from rlxd-proto and checked in; CI fails on drift
  tests/fixtures/        fake-claude scenarios
```

- **Who does what.** rlxd is the process host, the gate's enforcement point and the event bus. Python keeps the policy: prompts, the board, the fleet's rules, accounts.
- **How Python runs.** rlxd supervises one resident Python process, the brain (1.6).
- **How clients connect.** The TUI, rlxapp and Remote are clients of one socket (1.3). rlxd outlives every client.

### 1.1 The workspace and its CI on three OSes `independent`
- **What:** the workspace above.
  - `rust-toolchain.toml` pins the toolchain, and `cargo deny` checks licences and advisories.
  - `.github/workflows/rlxd.yml` runs on ubuntu-latest, macos-latest and windows-latest: `cargo fmt --check`, `cargo clippy --workspace -- -D warnings`, `cargo test --workspace --locked` and `cargo build --release`.
  - It also checks that `schemas/v1/` matches `rlxd-proto`, and it packages the archives of 1.2 as a workflow artifact.
  - It runs on every PR that touches `rlxd/**` (a sub-PR's lean CI included) and on every push to `rc/**`.
- **Accept:**
  - `cargo test --manifest-path rlxd/Cargo.toml --workspace --locked` exits 0 on each OS.
  - `gh run list -R AISquare-Studio/rlx --workflow rlxd.yml --branch rc/0.10.3 --limit 1 --json conclusion -q '.[0].conclusion'` prints `success`.
  - `gh run view <id> -R AISquare-Studio/rlx --json jobs -q '[.jobs[].name]'` names an ubuntu, a macos and a windows job.
  - `cargo run --manifest-path rlxd/Cargo.toml -p rlxd-proto --bin gen-schemas -- --check` exits 0.

### 1.2 The binaries ship with rlx releases, and where they live `independent` (`rlx daemon install` adds one line in cli/app.py beside :249)
- **Targets.** The release workflow builds `rlxd` and `rlxd-hook` for five targets:
  - aarch64-apple-darwin and x86_64-apple-darwin;
  - x86_64-unknown-linux-gnu and aarch64-unknown-linux-gnu;
  - x86_64-pc-windows-msvc.
- **Archives.** Each is a flat archive holding `rlxd` and `rlxd-hook` (`.exe` on Windows): `rlxd-<target>.tar.gz`, or `.zip` on Windows. They are attached to the GitHub Release `vX.Y.Z` with `rlxd-SHA256SUMS`.
- **One version.** rlxd's version is rlx's version.
- **Where rlxd lives.** In uv's tool bin directory beside `rlx` (`uv tool dir --bin`).
  - The installers (3.2) put it there, and `rlx upgrade` replaces it (4.2).
  - Someone who installed with plain `uv tool install` runs `rlx daemon install`. It downloads the archive matching `rlx --version`, checks it against `rlxd-SHA256SUMS` and installs it there.
  - Doctor names that fix when rlxd is missing (3.4).
  - publish.yml keeps shipping one pure wheel.
- **The client crate.** rlxapp depends on `rlxd-client` as a git dependency pinned to the release tag.
- **Accept** (pre-release form). The rlxd.yml run on the head uploads the artifact `rlxd-archives`:

  ```sh
  gh run download <id> -R AISquare-Studio/rlx -n rlxd-archives -D a && cd a
  for t in aarch64-apple-darwin x86_64-apple-darwin x86_64-unknown-linux-gnu aarch64-unknown-linux-gnu; do
    grep -q " rlxd-$t.tar.gz\$" rlxd-SHA256SUMS && tar -tzf "rlxd-$t.tar.gz" | grep -qx rlxd-hook || exit 1; done
  grep -q ' rlxd-x86_64-pc-windows-msvc.zip$' rlxd-SHA256SUMS && unzip -Z1 rlxd-x86_64-pc-windows-msvc.zip | grep -qx rlxd-hook.exe
  shasum -a 256 -c rlxd-SHA256SUMS
  ```

  - Every line exits 0.
  - `shasum -c` runs without `--ignore-missing`, so a listed archive that is missing fails it.
  - After an install, `test "$(rlxd --version)" = "rlxd $V"` holds.
  - `rm "$(uv tool dir --bin)/rlxd" && rlx daemon install && test -x "$(uv tool dir --bin)/rlxd"` exits 0 against the stub releases server.
  - **(release)** The same loop runs over `gh release download "v$V" -R AISquare-Studio/rlx -D r`.

### 1.3 The daemon: one per home, a local socket, a token `independent`
- **What:** `rlxd serve [--detach]`, `rlxd status --json`, `rlxd stop`, and `rlxd autostart on|off|status`.
- **One per home.** `<home>/rlxd/rlxd.lock` is held while rlxd runs, with the lock primitive of 4.1.
- **The socket.**
  - macOS and Linux: `<home>/rlxd/rlxd.sock`, in a 0700 directory, with mode 0600.
  - Windows: a named pipe, `\\.\pipe\rlxd-<hash of home>`, whose DACL holds one entry, for the current user's SID.
- **The token.** `<home>/rlxd/token` (0600) holds a random token, and `hello` requires it (7.2). Anything that can read the token already runs as the user.
- **Registration.** rlxd registers in the daemon registry (4.1).
- **Logs** rotate in `<home>/rlxd/logs/`.
- **Autostart.** It starts rlxd at login, for the TUI, Remote and the fleet:
  - macOS: a launchd LaunchAgent;
  - Linux: a systemd `--user` unit;
  - Windows: a Task Scheduler logon task.

  It does not make app-owned jobs run with the app quit (2.3).
- **Accept:**
  - `rlxd serve --detach && rlxd status --json | jq -e --arg v "$V" '.schema_version == 1 and .ok and .data.pid > 0 and .data.version == $v'` exits 0.

### 4.1 K. A registry of non-UI rlx processes, shared by Python and Rust `independent` (4.1a); `needs 0.10.2: #567, #554` (4.1b)
- **The files.** Everything sits in `<home>/daemons/` (0700), and each file is 0600:
  - `<id>.json` is the record. It is replaced whole: rlxd writes `<id>.json.tmp`, fsyncs it, then renames it.
  - `<id>.lock` is locked for the process's whole life.
  - `.gate.lock` is held while a daemon reads the others and writes its record.
  - `<id>` is 12 lowercase hex characters, as core/instances.py's `_ID` is.
- **The record.** Its schema is `rlxd/schemas/v1/daemon-record.json`: `{id, kind, pid, host, version, started_at, heartbeat_at, argv, restartable}`, with a heartbeat every 5 s. The kinds are `rlxd`, `brain`, `watch`, `serve`, `remote` and `board_watch`.
- **The lock primitive,** per OS, as core/locking.py takes it:
  - **POSIX:** `flock(fd, LOCK_EX | LOCK_NB)`.
  - **Windows:** a 1-byte lock at offset 0. Python takes it with `msvcrt.locking(fd, LK_NBLCK, 1)`, and rlxd with `LockFileEx(LOCKFILE_EXCLUSIVE_LOCK | LOCKFILE_FAIL_IMMEDIATELY)` on the same byte, which conflicts with it.
- **Liveness.**
  - A record is live while its lock is held. A record whose lock is free belongs to a dead process, whoever has its pid since.
  - An unreadable record counts as core/instances.py counts an unreadable asq record (`Unreadable`, :383-470): it is reported, never silently dropped.
  - Deleting a file follows #574's Windows rule: a delete refused with `PermissionError` is tried again for 1 s.
- **Items:**
  - **4.1a `independent`:** the registry, registering rlxd, the brain, `watch --detach` (services/watch.py) and `serve` (cli/serve.py).
    - It lives in `core/daemons.py`, on a new shared module, `core/registry.py`.
    - It edits no 0.10.2 file, so it does not touch `core/instances.py`, which #574 edits.
    - It must carry the lock-file rule of `core/instances.py` together with #574's Windows rule. Re-read #574 at its merged head.
    - `core/instances.py` moves onto `core/registry.py` in 6.2, after 0.10.2 has landed.
  - **4.1b `needs 0.10.2: #567 (services/remote_server.py), #554 (cli/watch.py)`:** Remote and `board -w` registered.
- **Accept:**
  - While rlxd runs, `rlx --json --schema-version 1 upgrade --check | jq -e '.data.daemons | map(.kind) | index("rlxd") != null'` exits 0, and likewise for each registered kind.
  - After `kill -9 "$(rlxd status --json | jq .data.pid)"`, the same check exits 1: the OS freed the lock.
  - `uvx check-jsonschema --schemafile rlxd/schemas/v1/daemon-record.json "$AISQUARE_HOME"/daemons/*.json` exits 0.
  - **Cross-language.** Both exit 0 on three OSes:
    - `uv run pytest tests/test_daemon_registry.py -q` starts the real rlxd binary and asserts that Python's registry reads its record as live. It then kills rlxd and asserts that the record reads as dead.
    - `cargo test --manifest-path rlxd/Cargo.toml -p rlxd --test registry_interop` locks a record through Python's `core.locking` and asserts that rlxd reads it as live.

### 4.2 K. The upgrade counts them, and stops and restarts them around the swap `independent` (on 4.1a)

## 5. Asks F–J

### 5.1 F. The gate decides every tool call, and fails closed `independent`
- **Two hooks into Claude Code, both required** (rlxapp architecture §8.1):
  - **PreToolUse, the primary.** For each run and each attempt, rlxd writes `<home>/rlxd/runs/<run_id>/<attempt>/settings.json`, passed with `--settings`. It holds one PreToolUse hook (matcher `*`) running `rlxd-hook pre-tool-use --run <run_id> --attempt <n>`. Its `timeout` is `deadline_ms / 1000 + 10` seconds, so Claude Code never ends the hook before rlxd's own deadline.
  - **Host permission prompts, the backstop.** The run uses `--permission-mode manual --permission-prompts host`. Any call that reaches Claude Code's permission check, because the hook was skipped or ended, becomes a host prompt. rlxd routes it to the same gate as `run.tool_call {via: "permission_prompt"}`.
  - The item's first probe confirms the `--permission-prompts host` protocol, and that `manual` prompts rather than allows.
- **Per-run files.** Nothing run-specific is written into the space's shared settings, so two runs in one space never collide. A resumed run gets a fresh file for its new attempt, under the same `run_id`, so attached and resumed runs stay gated.
- **How a call is decided.** rlxd's own rules come first, and deny with `by: "rlxd"`:
  - **The mount.** `no_tools` denies every call. `connectors` denies built-in tools and tools of connectors the mount doesn't name.
  - **The kind** (7.5):
    - `check`, `parse_instruction` and `widget_author` deny every call;
    - `widget_refresh` and `watch` deny any tool whose `read_only_hint` is `false`;
    - only `task` and `send_executor` may write.
  - **A pinned call** (`send_executor`, `watch`): a call whose tool or `input_sha256` differs from `pinned_call` is denied.

  Every other call becomes a `run.tool_call` to the app gate. The app answers with `run.decide {decision: allow | deny | draft, reason, draft_id?, stop?}`:
  - `draft` denies the call with the app's reason (rlxapp's "saved as draft; do not retry") and records the `draft_id`;
  - `stop: true` ends the run as `run.needs_you {reason: "denied"}`.

  The hook returns Claude Code's `permissionDecision`, with the reason as `permissionDecisionReason`.
- **The gate binding.**
  - `run.tool_call` goes to the app-role connections, keyed by `run_id`.
  - `run.decide` is accepted only from an app-role connection. Any other connection gets `not_gate`.
  - An attached or resumed run is decided the same way.
- **It fails closed.** The gate still sees every call, reads included, and fails closed; writes always need the live app.
  - With no app-role client connected, a call is denied (`by: "unreachable"`).
  - With no answer within `deadline_ms` (default 120,000), it is denied (`by: "timeout"`).
  - `rlxd-hook pre-tool-use` prints a deny and exits 0 on **any** failure: rlxd down, a bad reply, or its own timer. It never falls back to `rlx hook`, which has no `pre-tool-use` handler ([cli/hook.py:155-315](https://github.com/AISquare-Studio/rlx/blob/c6b523c3/src/aisquare/cli/hook.py#L155-L315)).
- **The call ledger.** For every gated call, rlxd records `decided`, then `executing`, then `ok` or `error`. Each record is fsynced before the hook replies. rlxd never retries a call. After a crash, a call left `executing` reads `unknown`, so "may have sent" is told apart from "sent" (5.4).
- **The input hash.** `input_sha256` is the SHA-256, in hex, of the input's RFC 8785 canonical JSON. For example, `{"b":1,"a":"x"}` canonicalises to `{"a":"x","b":1}`, whose hash is `cdab067e9f3beb32d1252cfd63e492592fecbf591b0d08cadb24bb17f3864246`.
- **Why it matters.** Send safety depends on this: rlxapp's Draft, Standing approval and Auto modes can only be enforced if the app decides every connector call.
- **Accept** (fake-claude, three OSes, using the conventions' helpers):
  - **A deny reaches Claude Code.** Use `fake-claude/slack-send`. It asks once for `mcp__claude_ai_Slack__slack_send_message` with the input in `slack-send/input.json`, then waits:

    Both jq checks exit 0. (The fixture's input has only strings and integers, so `json.dumps` with sorted keys is its RFC 8785 form.)
  - **An allow runs the tool.** `decide allow ok` gives `.starts[-1].tool_ran == true`, and the ledger reads `ok`: `rlxd call run.get "{\"run_id\":\"$r\"}" | jq -e --arg c "$c" '.data.calls | map(select(.call_id == $c)) | length == 1 and .[0].state == "ok" and .[0].decision == "allow"'` exits 0.

### 5.4 I. The run lifecycle `independent`
- **Run IDs are session IDs.** The app picks each `run_id`, a UUID that rlxd passes as `--session-id`. rlxd refuses a duplicate (`run_exists`).
- **Session-less runs.** `persist_session: false` passes `--no-session-persistence`, as rlxapp's tool-less, session-less `Check` needs (rlxapp architecture §8.3). That is the default for every kind but `task`, because only Tasks persist (§14). Such a run has no session to resume.
- **Listing.** `run.list` lists every run rlxd knows, live or ended, including runs from before an app or rlxd restart.
- **Attaching.** `run.events {run_id, from_run_seq}` replays the run's durable log from `from_run_seq`, then follows live. It doesn't depend on the ring buffer, so an app that was closed for a day still catches up.
- **Resume.** `run.resume {run_id, reply?}` resumes only runs rlxd reports dead: ended, or `failed {reason: "engine_restarted"}`. It uses `--resume <run_id>`, keeps the `run_id`, and starts a new attempt. It refuses:
  - a live run (`run_alive`);
  - a session-less run (`no_session`);
  - a `send_executor` (`not_resumable`), because a send is never retried.
- **The send outcome.** `run.get` returns every gated call's ledger record (5.1), so the app can tell "sent" (`ok`), "not sent" (denied, or `error`) and "may have sent" (`unknown`).
- **The handshake.** `hello` exchanges `protocol_version` (7.2).
- **Cancel.** `run.cancel` kills the process tree and keeps the partial text.
- **After an rlxd restart,** runs that were in flight end `failed {reason: "engine_restarted"}` and keep their `run_id`, so the app can resume them.
- **Accept:** 7.2 and 7.5.

### 5.5 J. Runs name their connectors, and no turn starts until they are connected `independent`
- **Why:** headless Claude Code loads claude.ai connectors only while stdin is open, and only those connected by the time it writes `system/init` (rlxapp architecture §4, E6 and E9):

  - with stdin held open, both connectors were `connected` in one run, while in another one was still `pending`.

- **What:** `run.start` takes `needs_connectors` (7.5).

    ```python
    """Exit 0 when tests/ changed between two revisions only in imports and in which fleet module a name is reached through."""
    import ast, subprocess, sys

    PKG = "aisquare.services.fleet"

    def git(*args):
        r = subprocess.run(["git", *args], capture_output=True, text=True)
        return r.stdout if r.returncode == 0 else None

    def subs(rev):
        out = git("ls-tree", "--name-only", f"{rev}:src/aisquare/services/fleet") or ""
        return {n[:-3] for n in out.split() if n.endswith(".py") and n != "__init__.py"}

    class Norm(ast.NodeTransformer):
        def __init__(self, tree, sub):
            self.sub, mods = sub, {PKG, *(f"{PKG}.{s}" for s in sub)}
            self.alias = set()
            for n in ast.walk(tree):
                if isinstance(n, ast.Import):
                    self.alias |= {a.asname for a in n.names if a.asname and a.name in mods}
                elif isinstance(n, ast.ImportFrom) and n.module:
                    self.alias |= {a.asname or a.name for a in n.names if f"{n.module}.{a.name}" in mods}
        def visit_Import(self, node): return None
        def visit_ImportFrom(self, node): return None
        def visit_Name(self, node):
            return ast.Name("FLEET", node.ctx) if node.id in self.alias else node
        def visit_Attribute(self, node):
            self.generic_visit(node)
            v = node.value
            if isinstance(v, ast.Name) and v.id == "FLEET" and node.attr in self.sub:
                return v
            return node
        def visit_Constant(self, node):
            s = node.value
            if isinstance(s, str) and (s == PKG or s.startswith(PKG + ".")):
                parts = s[len(PKG):].lstrip(".").split(".") if s != PKG else []
                if parts and parts[0] in self.sub:
                    parts = parts[1:]
                return ast.Constant(".".join(["FLEET", *parts]))
            return node

    def norm(src, sub):
        tree = ast.parse(src)
        return ast.dump(Norm(tree, sub).visit(tree))

    pre, post = sys.argv[1:3]
    sub = subs(pre) | subs(post)
    bad = []
    for path in (git("diff", "--name-only", pre, post, "--", "tests/") or "").split():
        a, b = git("show", f"{pre}:{path}"), git("show", f"{post}:{path}")
        if not path.endswith(".py") or a is None or b is None or norm(a, sub) != norm(b, sub):
            bad.append(path)
    print("\n".join(bad))
    sys.exit(1 if bad else 0)
    ```

### 7.2 The JSON envelope, and the `hello` handshake `independent`
- **CLI.** Under `--json --schema-version 1`, every command prints exactly one document. Under `--json-lines`, every line is an event envelope (7.3).

  ```json
  {"schema_version": 1, "ok": true, "data": {}}
  {"schema_version": 1, "ok": false, "error": {"code": "not_a_tty", "message": "…", "hint": "…", "detail": "…"}}
  ```

  - Exit codes: 0 when `ok`, 1 when refused or failed, 2 on a usage error, and 70 when not implemented.
  - `hint` and `detail` are optional.
- **Socket.** Requests are newline-delimited JSON, `{"id": 7, "method": "run.start", "params": {}}`. Each response is the same envelope plus `"id": 7`.
- **`hello`, the protocol handshake.** The first frame is `hello {token, protocol_version, client, client_version, role: app | tui | remote | cli, capabilities, env?}`.
  - The reply is `{protocol_version, protocol_versions: [1], rlxd_version, capabilities}`.
  - A `protocol_version` whose major rlxd doesn't serve gets `incompatible_protocol`, with `detail.supported`. It never gets a silent misparse: rlxapp then reports `Incompatible` and offers an update.
  - A wrong token, or any other first frame, gets `unauthorized`.
  - `schema_version` in every envelope is the protocol version.
- **Versioning.**
  - New fields and new event types keep the version, and clients ignore what they don't know.
  - Removing or renaming a field raises the major version, and rlxd serves the old one for one minor release.
- **Accept:**
  - `rlxd call status > s.json; uvx check-jsonschema --schemafile rlxd/schemas/v1/envelope.json s.json` exits 0.
  - `printf '{"id":1,"method":"status"}\n' | rlxd call --raw` exits 1 with `.error.code == "unauthorized"`.
  - `rlxd call --protocol-version 99 status` exits 1 with `.error.code == "incompatible_protocol" and (.error.detail.supported | index(1) != null)`.
  - `rlxd call status | jq -e '.data.protocol_version == 1 and (.data.capabilities | type == "array")'` exits 0.
  - `rlxd call no.such.method` exits 1 with `.error.code == "unknown_method"` and a non-empty `.error.message`.

### 7.5 The runner: start, stream, tool-call decision, needs-you, done, failed, cancel `independent`

**`run.start` params.** It returns `{run_id}`:

```json
{"run_id": "uuid", "kind": "task", "prompt": "…",
 "mount": {"kind": "connectors", "connectors": ["claude.ai Slack"]},
 "needs_connectors": ["claude.ai Slack"], "output_schema": {},
 "persist_session": true, "space": "default", "append_system_prompt": "…",
 "partial": true, "timeout_s": 900, "deadline_ms": 120000,
 "pinned_call": null,
 "needs_you_when": {"pointer": "/status", "equals": "needs_you", "question_pointer": "/question"}}
```

- `run_id` is chosen by the app and is Claude Code's `--session-id` (5.4).
- `kind` is one of `task`, `send_executor`, `widget_refresh`, `watch`, `check`, `parse_instruction` and `widget_author`. rlxd's rules for each are in 5.1. `check`, `parse_instruction` and `widget_author` require `mount: {kind: "no_tools"}`; any other mount is refused with `kind_mount_mismatch`.
- `mount` is `{kind: "no_tools"}` (`--tools "" --strict-mcp-config`) or `{kind: "connectors", connectors: [...]}` (`--tools ""`; the gate enforces which tools may be called).
- `needs_connectors` names the connectors that must be `connected` before the first turn (5.5). An empty list means none.
- `persist_session` defaults to `false` for every kind but `task`. With `false`, rlxd passes `--no-session-persistence`, `run.done.session` is `null`, and `run.resume` refuses with `no_session`.
- `pinned_call: {tool, input_sha256}` is required for `send_executor` and for a `watch` run (5.1).
- `needs_you_when` tells rlxd when a finished run is needs-you rather than done.

**The run's states:**
- `queued` → `running`;
- `running` → `done`, `failed` or `needs_you`;
- `needs_you`, or a dead run → `running` again through `run.resume` (a new attempt, same `run_id`);
- any state → `failed {reason: "cancelled"}` through `run.cancel`.

**Run events** (topic `run`). Every one carries `run_id`, `run_seq`, `kind`, `attempt` and `job_id?`. `call_id` is Claude Code's `tool_use_id`, so one call's `run.tool_call`, `run.tool_decided` and `run.tool_result` share it.

| Type | When | `data`, besides the common fields |
|---|---|---|
| `run.queued` | over `max_concurrent_runs` | `position` |
| `run.started` | stream-json `system/init`, once every connector in `needs_connectors` is `connected` (5.5) | `cwd, model, tools[], mcp_servers[{name,status}], claude_version, resumed: bool` |
| `run.text` | `assistant` text; partial chunks when `partial` | `text, partial` |
| `run.tool_call` | the PreToolUse hook or a host permission prompt (5.1); **the app must answer `run.decide`** | `call_id, tool, input, input_sha256, via: hook\|permission_prompt, deadline_ms` |
| `run.tool_decided` | after the decision | `call_id, decision: allow\|deny\|draft, by: app\|rlxd\|timeout\|unreachable, reason, draft_id?` |
| `run.tool_result` | a `tool_result` block in a stream-json `user` message | `call_id, tool, is_error, content, truncated`. `content` is the block's content exactly as Claude Code emitted it, up to 1 MiB, and `truncated` says whether it was cut. rlxapp's watches read `match.path` from it (rlxapp architecture §8.2) |
| `run.rate_limited` | `rate_limit_event` | `resets_at?` |
| `run.needs_you` | `needs_you_when` matched the final output, or the app's `run.decide` had `stop: true` | `reason: question\|denied, question?, call_id?` |
| `run.done` | `result`, success | `session, result, structured_output?, usage{input_tokens,output_tokens}, cost_usd?, duration_ms, num_turns` |
| `run.failed` | error, timeout, cancel, engine restart, or a connector-gate miss (5.5) | `reason: cancelled\|error\|timeout\|rate_limited\|engine_restarted\|connectors, message, partial_text, connectors?[{id,status}]` |

**The commands:**

### 7.6 Scheduler jobs and events `independent`

rlxapp owns its jobs' definitions. rlxd fires them and keeps the run records (2.3). App-owned scheduled jobs fire only while an app gate client is connected; with no app, rlxd records `job.skipped {reason: app_absent}`.

**`job.put` params.** It creates or replaces the job by `job_id`, idempotently, and returns `{job_id}`. A job is one of two types:

```json
{"job_id": "slack-digest", "type": "run", "schedule": {"every_minutes": 15},
 "run": {"kind": "widget_refresh", "prompt": "…", "mount": {"kind": "connectors", "connectors": ["claude.ai Slack"]},
         "needs_connectors": ["claude.ai Slack"], "output_schema": {}, "space": "default"},
 "catch_up": "once", "enabled": true}
{"job_id": "ci-green", "type": "watch", "every": {"minutes": 5},
 "connector": "claude.ai GitHub", "tool": "mcp__claude_ai_GitHub__get_check_runs", "input": {"ref": "main"},
 "catch_up": "skip", "enabled": true}
```

- `schedule` is `{"every_minutes": N}` or `{"cron": "*/15 * * * *", "tz": "Europe/London"}`. The first fire comes one interval after `job.put`, or at the next cron match.
- A `run` job's `run` is a 7.5 `run.start` template. rlxd picks each fire's `run_id`.
- A `watch` job makes one pinned call per tick, with no prompt.
  - Where `connectors.call` is available (5.3), the call is made through it.
  - Otherwise it runs a `watch` run with rlxd's fixed prompt, "Call this tool once with exactly this input; do nothing else", and with `pinned_call` set to the input's hash, so connector text can't steer the call.
  - Either way, the call's raw result arrives as `job.watch_result`. rlxapp evaluates `match` itself.
- `catch_up` (`once` or `skip`) applies when the app reconnects after `app_absent` skips, and after fires missed while rlxd was down.

**The other methods:**
- `job.list` returns `jobs[]`, each with `job_id`, `type`, `next_fire_at`, `last_fire_at`, `last_run_id`, `last_state` and `skipped_count`.
- `job.delete`, `job.pause`, `job.resume`.
- `job.run_now` returns `{run_id}`. It needs an app gate client too.

**Job events** (topic `job`):
- `job.put` and `job.deleted`, each with `{job_id}`;
- `job.paused` and `job.resumed`, each with `{job_id}`;
- `job.fired {job_id, run_id, scheduled_for, fired_at}`;
- `job.skipped {job_id, scheduled_for, reason: overlap | paused | rate_limited | app_absent | missed}`;
- `job.watch_result {job_id, run_id?, tool, input_sha256, content}`.

A fired job's run then emits the 7.5 events, with `job_id` set.

**Accept** (with `RLXD_CLAUDE_BIN=…/fake-claude/hello` unless a check names another fixture):

## Owner steps around 0.10.3 (not the train's work, listed for context)

1. **Signing for the rlxd binaries** `independent`. macOS needs notarization, Windows needs Authenticode, and both come from the same certificates as rlxapp's own. Who holds them is an open question in rlxapp's architecture (§16, owner question 6).
   - **Accept:** on macOS, `codesign --verify --strict rlxd && spctl -a -t exec -vv rlxd` exits 0. On Windows, `(Get-AuthenticodeSignature rlxd.exe).Status` prints `Valid`.
2. **A claude.ai-signed-in runner for the `[real]` checks** `independent`. The `[real]` checks need Claude Code signed in with claude.ai, not an API key. Until a runner has such a login, they run by hand and the sub-PRs record their output.
   - **Accept:** if a nightly leg gets one, `claude auth status --json | jq -e '.loggedIn == true and .authMethod == "claude.ai"'` exits 0 on it.
3. **Release approval** `needs 0.10.2: 0.10.2 released first, so versions stay in order`. Approve the version bump to 0.10.3 and the dated CHANGELOG, as for 0.10.1.
   - **Accept:** `grep -q '^version = "0.10.3"' pyproject.toml && grep -qE '^## \[0\.10\.3\] - 20[0-9]{2}-' CHANGELOG.md` exits 0.

## How the train runs (keep what helps)

- **In parallel with 0.10.2.** This train has its own manager and its own checkout.
  - Start with the `independent` items: rlxd first (1.1-1.7), then 2.x, 3.3's bus, 4.1a, 4.2, 4.3, 5.1, 5.3, 5.4, 5.5 and 7.x.
  - Once #578 is on `main`, do 3.1 A1. Until then, the checks that pass `--schema-version 1` wait.
  - Once 0.10.2 has landed on `main`, merge `main` into `rc/0.10.3`.
  - Then do 6.1, 1.8, 6.2, 1.9, and the rest tagged `needs 0.10.2`.
- **Release train** (as 0.10.1 and 0.10.2 ran). Feature sub-PRs into `rc/**` get lean CI (Linux only) plus `rlxd.yml` (three OSes) when they touch `rlxd/**`. The full matrix runs on a push to `rc/**`, or on a dispatch (`gh workflow run ci.yml --ref <branch>`). For each sub-PR:
  - dispatch the full matrix on its exact head;
  - have a tester verify that exact sha;
  - merge with `--match-head-commit <sha>`;
  - then watch rc's own push run.
- **Runners.** The runner pool is shared org-wide, and now with a second train.
  - Each push to `rc/**` also starts a duplicate full run for the rc -> main draft PR. Cancel it.
  - Pause merging while a gate run waits for runners.
- **Windows-only traps seen:**
  - "/" or "~" paths, or `str(Path)` compared with drawn text;
  - fleet calls without the in-memory tmux;
  - a stand-in binary that `shutil.which` cannot see on Windows (no PATHEXT);
  - widget ids reused before Textual frees them;
  - Textual timers holding executor threads.

  Reproduce them on macOS by taking tmux off PATH, clearing the stand-in's exec bit, or using PureWindowsPath. For rlxd, also: named pipes are not files, ConPTY needs Windows 10 1809 or later, Job Objects must be created before the child starts, and Windows locks are byte-range locks (4.1).
- **Before a coder says ready:**
  - Run every test file that imports a changed module, plus every test that greps a changed string.
  - Paste each gate's last line: ruff check, ruff format --check, mypy, mypy --platform win32; for `rlxd/`, cargo fmt --check, cargo clippy -D warnings, and cargo test on all three OSes.
  - Run every new or changed check in this file once against a deliberately broken input, and paste that it exits non-zero.
- **Nightly legs.** The `latest` Claude Code and Codex legs catch upstream drift. Stream-json, `system/init`, the hook replies and `--permission-prompts host` are upstream formats, so the fake-claude scenarios are re-recorded from the `[real]` runs whenever they change.
