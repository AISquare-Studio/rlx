# rlx 0.10.3: handoff ("rlx for apps")

This branch, `rc/0.10.3`, is the release train for **rlx for apps**. It starts from `main` at v0.10.1 (c6b523c3).

**It runs in parallel with 0.10.2.** A separate manager, in a separate checkout, runs 0.10.3 while 0.10.2's train (`rc/0.10.2`, PR #545) is still open. **Once 0.10.2 has landed on `main`, that manager merges `main` into `rc/0.10.3`**, and only then starts the items tagged `needs 0.10.2`.

rlxapp's manager wrote this file at the owner's request, following the owner's decisions (2026-11-25). rlxapp is the desktop app for people who don't use a terminal (AISquare-Studio/rlxapp). It builds against an `Engine` interface, defined in rlxapp's `docs/architecture.md` (rlxapp PR #1). Until this train ships, the app runs on a fake engine. Section 8 maps each `Engine` call to the contract item here that serves it.

## What 0.10.3 ships

- **rlxd, the engine.** A long-running local daemon written in Rust. It replaces tmux as the process host and lives in this repo as a Cargo workspace (`rlxd/`). It has its own CI on three OSes, and its binaries ship with rlx releases. Python stays the orchestration brain and the TUI.
- **What the app needs, on rlxd:**
  - a tmux-free headless runner that turns Claude Code's stream-json output into structured events;
  - native Windows;
  - a user-defined scheduler;
  - a connector surface;
  - a home for non-developers that is not a project folder.
- **Asks A–D:** a versioned JSON envelope, a silent installer, a local event stream, and native Windows for install, accounts, upgrade and doctor.
- **What the ask-E answers require (ask K):** non-UI rlx processes, rlxd included, that the upgrade counts and can stop and restart, and Keychain variables passed through.
- **Asks F–J:**
  - F: the app decides every tool call;
  - G: sign-in without a TTY;
  - H: connector listing with read/write hints;
  - I: session IDs and cancel passed through;
  - J: runs name their connectors, and no turn starts until they are connected.
- **The app contract:**
  - every command the app calls;
  - one JSON envelope with `schema_version`;
  - the event stream;
  - runner, scheduler and connector events;
  - install, upgrade and sign-in as JSON lines.
- **Engineering:** `services/fleet.py` (19,686 lines) is split into cohesive modules, followed by a DRY pass across services and tests.

## How to read the checks

Every item ends with an **Accept** check: commands, plus the exit code or output shape they must produce. The checks rely on these conventions.

- **`AISQUARE_HOME`** points at a fresh temporary home for each check, so no check touches a real home.
- **`rlxd call <method> [<params-json>]`** sends one request and prints the response envelope (7.2). Exit codes: 0 when `ok`, 1 when not `ok`, 3 when rlxd isn't running.
- **`rlxd events [--topics a,b] [--since SEQ] [--follow] [--until TYPE] [--limit N] [--timeout S]`** prints event envelopes (7.3) as JSON lines. It exits 0 once `--until`'s type is seen, and 4 on timeout.
- **`RLXD_CLAUDE_BIN=rlxd/tests/fixtures/fake-claude/<scenario>`** makes rlxd run a stand-in for `claude`. The stand-in replays recorded stream-json, in the shape rlxapp's architecture recorded (§4 and §18, E6 and E9). Every check therefore runs in CI on three OSes with no model turn.
- **The fixture's log.** Each scenario writes `$AISQUARE_HOME/fake-claude.log.json`, which checks read. It holds:
  - the argv it was given;
  - the stdin messages, with their times;
  - whether stdin hit EOF before `system/init`;
  - its hook replies;
  - whether its tool ran;
  - its start count.
- **Subscribe first.** A check that starts a run first reads the current `seq` (`s=$(rlxd call status | jq .data.seq)`), then reads events `--since "$s"`, so no event is missed.
  - Every jq check filters on its own `run_id` or `job_id`.
  - Every `index` is compared with `!= null`, and every order check requires each event it orders.
  - An empty stream fails.
- **`--as-app`** makes a CLI client say `hello {role: "app"}`, as rlxapp does.
- **`[real]`** marks a check that also runs nightly against the real Claude Code (the `latest` leg).
- **Schemas** live in `rlxd/schemas/v1/`. `uvx check-jsonschema --schemafile <schema> <file>` validates against them.

## 1. rlxd: the engine

```
rlxd/                    Cargo workspace (this repo)
  crates/rlxd-proto/     wire types, schema_version, JSON Schemas (schemars); no I/O
  crates/rlxd-client/    the library rlxapp depends on: connect, call, subscribe
  crates/rlxd/           the daemon: PTY host, runner, scheduler, hook intake, event bus
  crates/rlxd-hook/      the tiny hook client
  schemas/v1/            generated from rlxd-proto and checked in; CI fails on drift
  tests/fixtures/        fake-claude scenarios
```

- **Who does what.** rlxd is the process host and event bus. Python keeps the policy: prompts, the board, the fleet's rules, accounts.
- **How Python runs.** rlxd supervises one resident Python process, the brain (1.6).
- **How clients connect.** The TUI, rlxapp and Remote are clients of one socket (1.3).

### 1.3 The daemon: one per home, a local socket, a token `independent`
- **What:** `rlxd serve [--detach]`, `rlxd status --json`, `rlxd stop`, and `rlxd autostart on|off|status`.
- **One per home.** `<home>/rlxd/rlxd.lock` is held while rlxd runs, as the instances registry's locks are.
- **The socket.**
  - macOS and Linux: `<home>/rlxd/rlxd.sock`, in a 0700 directory, with mode 0600.
  - Windows: a named pipe, `\\.\pipe\rlxd-<hash of home>`, whose ACL admits only the current user.
- **The token.** `<home>/rlxd/token` (0600) holds a random token, and `hello` requires it (7.2).
- **Registration.** rlxd registers in the daemon registry (4.1).
- **Logs** rotate in `<home>/rlxd/logs/`.
- **Autostart.** It starts rlxd at login, so the scheduler runs with the app closed:
  - macOS: a launchd LaunchAgent;
  - Linux: a systemd `--user` unit;
  - Windows: a Task Scheduler logon task.
- **Accept:**
  - `rlxd serve --detach && rlxd status --json | jq -e '.schema_version==1 and .ok and .data.pid>0 and .data.version=="0.10.3"'` exits 0.
  - A second `rlxd serve` exits 1 with `.error.code=="already_running"`.
  - `rlxd call --token wrong status` exits 1 with `.error.code=="unauthorized"`.
  - Socket and token permissions: on macOS, `stat -f %Lp <home>/rlxd/rlxd.sock <home>/rlxd/token` prints `600` twice; on Linux, `stat -c %a` does.
  - Windows: `rlxd status --json | jq -e '.data.pipe_acl=="current_user"'`.
  - `rlxd stop` exits 0, after which `rlxd status --json` exits 3 with `.error.code=="not_running"`.
  - `rlxd autostart on`, then:
    - macOS: `launchctl print gui/$(id -u)/studio.aisquare.rlxd` exits 0;
    - Linux: `systemctl --user is-enabled rlxd.service` prints `enabled`;
    - Windows: `schtasks /Query /TN rlxd` exits 0.

### 1.4 The PTY host, which replaces tmux as the process host `independent`
- **What:** PTYs through `portable-pty`, using ConPTY on Windows, with a VT screen model. The methods:
  - `pty.spawn {argv, cwd, env, cols, rows, label}` returns `{pty_id}`;
  - `pty.write {pty_id, text | keys | paste}`, where `paste` is a bracketed paste, as `paste-buffer -p` is today;
  - `pty.resize`;
  - `pty.screen` returns `{text (ANSI), cursor, cols, rows, exited, status}`;
  - `pty.subscribe {pty_id, read_only}`;
  - `pty.kill` and `pty.list`.
- **The frame is today's.** `pty.screen` returns the frame the TUI builds today from `capture-pane -e` and `display-message` ([core/tmux.py:9-13](https://github.com/AISquare-Studio/rlx/blob/c6b523c3/src/aisquare/core/tmux.py#L9-L13)), so the TUI's renderer is reused.
- **Panes outlive clients.** A PTY outlives every client. A process that has ended keeps its last screen and exit status until it is killed, as `remain-on-exit on` does today.
- **Unforgeable IDs.** A `pty_id` is 128 random bits, and the fleet's launch record stores it. So the launch-seal rule carries over: act only where the record places the pane.
- **Escape hatch.** `rlxd attach <pty_id>` replaces `tmux -L asq attach`.
- **Accept:** tests in `rlxd/crates/rlxd/tests/pty.rs` run on three OSes and exit 0. By hand:
  - Spawn: `id=$(rlxd call pty.spawn '{"argv":["sh","-c","echo ready; sleep 30"],"cols":80,"rows":24}' | jq -r .data.pty_id)`. On Windows the argv is `["cmd","/c","echo ready & timeout /t 30"]`.
  - `rlxd call pty.screen "{\"pty_id\":\"$id\"}" | jq -e '.data.text|contains("ready")'` exits 0.
  - Disconnect the client and reconnect: `rlxd call pty.list | jq -e --arg id "$id" '.data.ptys | map(.pty_id) | index($id) != null'` exits 0.
  - After `sh -c 'exit 3'` ends, `pty.screen` gives `.data.exited==true and .data.status==3`.

### 1.5 Hooks over the socket `independent`
- **What:** `rlxd-hook <event>` reads Claude Code's hook JSON on stdin, hands it to rlxd, prints rlxd's reply and exits 0. rlxd passes the event to the resident brain (1.6), so no Python starts for each hook.
- **Why:**
  - Today each hook runs `aisquare hook <event>`, a fresh Python process ([cli/hook.py:1-12](https://github.com/AISquare-Studio/rlx/blob/c6b523c3/src/aisquare/cli/hook.py#L1-L12)).
  - The session-end hook spends about 0.25 s of its 0.37 s importing (0.10.2's handoff).
- **With rlxd not running,** `rlxd-hook` execs `rlx hook <event>`, today's path, so no board update is lost.
- **Like today's hooks,** any failure exits 0.
- **Hook installation** moves to `rlxd-hook` in 1.8.
- **Accept:**
  - `p='{"session_id":"t1","hook_event_name":"SessionStart","cwd":"."}'; echo "$p" | rlxd-hook session-start; echo $?` prints `0`.
  - `rlxd events --topics hook --since 0 | jq -s -e 'map(select(.type == "hook.session_start" and .data.session_id == "t1")) | length == 1'` exits 0.
  - `hyperfine -N --runs 20 --export-json h.json 'rlxd-hook ping' && jq -e '.results[0].median < 0.03' h.json` exits 0.
  - With rlxd stopped, the output equals `rlx hook session-start`'s for the same stdin: `diff <(echo "$p" | rlxd-hook session-start) <(echo "$p" | rlx hook session-start)` exits 0.

- **Files:** it adds `cli/brain.py` and `services/brain.py`. It also adds one hidden registration line in `cli/app.py`, beside line 249, away from #555's hunks.
- **Accept:**

### 1.7 The event bus, pushed to every client `independent`

### 5.1 F. The app decides every tool call `independent`
- **What:** for each run, rlxd writes a PreToolUse hook (matcher `*`) into the space's settings and passes it with `--settings`. The hook runs `rlxd-hook pre-tool-use --run <run_id>`.
- **How a call is decided:**
  1. A tool outside the run's `allowed_tools` is denied by rlxd at once (`by: "rlxd"`).
  2. Every other call becomes a `run.tool_call` event to the app.
  3. The app answers with `run.decide`.
  4. The hook returns Claude Code's `permissionDecision` (allow or deny) with the app's reason.
- **Failing closed.**

- **After an rlxd restart,** runs that were in flight end `failed {reason: "engine_restarted"}` and keep their `session_id`, so the app can resume them.
- **Accept:** 7.5.

### 5.5 J. Runs name their connectors, and no turn starts until they are connected `independent`
- **Why:** headless Claude Code loads claude.ai connectors only while stdin is open, and only those connected by the time it writes `system/init` (rlxapp architecture §4, E6 and E9):
  - with stdin at EOF, `system/init` listed no servers and no connector tools, in 3 runs of 3;
  - with stdin held open, both connectors were `connected` in one run, while in another one was still `pending`.

  A widget run that starts before Slack connects would report "nothing needs you".
- **What:** `run.start` takes `needs_connectors` (7.5).
  - rlxd keeps stdin open (2.1). It sends the first user message only once every named connector is `connected`.
  - It waits up to `connector_wait_s` (default 15) for them.
  - While one is `pending` or absent, it restarts the session with backoff (2 s, 5 s, 10 s), 3 tries in all. It stops at once when one is `needs-auth` or `failed`.
  - The run then ends `run.failed {reason: "connectors", connectors: [{id, status}]}`, naming each named connector that is not `connected`, with its status (`pending`, `needs-auth`, `failed` or `absent`). No `run.text` or `run.done` is delivered for it.
  - A failure with a `needs-auth` connector also raises `needs_you.raised` (7.3).
- **The first step is a probe:** how Claude Code reports connector states before the first turn under `--input-format stream-json`. If it reports them only in the `system/init` that follows the first message, rlxd sends that message, reads `system/init`, and on a miss cancels at once, delivering nothing from that try. rlxapp discards unconfirmed output either way (rlxapp architecture §4).
- **Accept:** fake-claude scenarios on three OSes, each started as in 2.1 with `"needs_connectors":["claude.ai Slack"]`, and with `ev.jsonl` holding the run's events up to `run.done` or `run.failed`:
  - **Late.** `connectors-late` reports Slack `pending` for 3 s, then `connected`. Two checks exit 0:
    - `jq -s -e --arg r "$r" 'map(select(.type == "run.started" and .data.run_id == $r)) | length == 1 and (.[0].data.mcp_servers | map(select(.name == "claude.ai Slack")) | (length == 1 and .[0].status == "connected"))' ev.jsonl`;

  - **Never.** `connectors-never` leaves Slack `pending`. `jq -s -e --arg r "$r" 'map(select(.data.run_id == $r)) | .[-1].type == "run.failed" and .[-1].data.reason == "connectors" and .[-1].data.connectors == [{"id":"claude.ai Slack","status":"pending"}] and (map(select(.type == "run.text" or .type == "run.done")) | length == 0)' ev.jsonl` exits 0, and the fixture log has `.starts == 3`.

    None ends `run.done` without Slack.

### 7.2 The JSON envelope, with `schema_version` `independent`
- **CLI.** Under `--json --schema-version 1`, every command prints exactly one document:

  ```json
  {"schema_version": 1, "ok": true, "data": {}}
  {"schema_version": 1, "ok": false, "error": {"code": "not_a_tty", "message": "…", "hint": "…", "detail": "…"}}
  ```

  - Exit codes: 0 when `ok`, 1 when refused or failed, 2 on a usage error, and 70 when not implemented.
  - `hint` and `detail` are optional.
- **Socket.** Requests are newline-delimited JSON, `{"id": 7, "method": "run.start", "params": {}}`. Each response is the same envelope plus `"id": 7`.
- **`hello`.** The first frame is `hello {token, client: "rlxapp", client_version, role: app | tui | remote | cli, env?}`. Its reply carries `{daemon_version, schema_versions: [1], capabilities: [...]}`. Any other first frame gets `unauthorized`.
- **Versioning.**
  - `schema_version` is an integer.
  - New fields and new event types keep the version, and clients ignore what they don't know.
  - Removing or renaming a field raises the version, and rlxd serves the old one for one minor release.
- **Accept:**
  - `rlxd call status > s.json; uvx check-jsonschema --schemafile rlxd/schemas/v1/envelope.json s.json` exits 0.
  - `printf '{"id":1,"method":"status"}\n' | rlxd call --raw` exits 1 with `.error.code=="unauthorized"`.
  - `rlxd call no.such.method` exits 1 with `.error.code=="unknown_method"` and a non-empty `.error.message`.

### 7.3 The event stream `independent`
- **Subscribing.** `events.subscribe {topics: [...], since?: seq}` streams every event the ring buffer still holds after `since`, then live events. Each event:

  ```json
  {"schema_version": 1, "seq": 42, "time": "2026-11-25T12:00:00.000Z", "topic": "run", "type": "run.text", "data": {}}
  ```

- **Order and gaps.** `seq` increases strictly per home. If `since` is older than the buffer, the stream starts with `daemon.gap {from, to}`, and the app re-reads state with `run.list` and `job.list`.
- **Topics and their types:**
  - `daemon`: started, stopping, gap;
  - `run`: 7.5;
  - `job`: 7.6;
  - `connector`: 7.7;
  - `pty`: output, exited;
  - `hook`: session_start, prompt_submit, session_end, pre_tool_use;
  - `fleet`: agent.spawned, agent.state, agent.ended;
  - `board`: task.changed, note.added;
  - `needs_you`: raised and cleared. Runs raise them with 7.5's `run.needs_you`, or with 5.5's connector failure when a connector is `needs-auth`; fleet agents raise them too;
  - `upgrade`: started, done.
- **Accept:**

  ```sh
  s=$(rlxd call status | jq .data.seq)
  r=$(rlxd call run.start '{"kind":"task","prompt":"hi","allowed_tools":[],"session_id":"6f1c2b9e-0000-4000-8000-000000000003","space":"default"}' | jq -r .data.run_id)
  rlxd events --topics run --since "$s" --follow --until run.done --timeout 30 > ev.jsonl
  jq -s -e 'length > 0 and ([.[].seq] as $q | $q == ($q | sort | unique))' ev.jsonl
  jq -s . ev.jsonl > evs.json && uvx check-jsonschema --schemafile rlxd/schemas/v1/event-list.json evs.json
  ```

  - Both checks exit 0. The first exits 1 on an empty stream, or on a repeated or out-of-order `seq`.
  - Nothing repeats after a reconnect: `rlxd events --topics run --since "$(jq -s '.[-1].seq' ev.jsonl)" | jq -s -e 'length == 0'` exits 0.
  - A gap is reported: in a test build, after `rlxd call debug.emit '{"count":10001}'`, `rlxd events --since 0 --limit 1 | jq -e '.type == "daemon.gap"'` exits 0.

### 7.5 The runner: start, stream, tool-call decision, needs-you, done, failed, cancel `independent`

**`run.start` params.** It returns `{run_id}`:

```json
{"kind": "task", "prompt": "…", "allowed_tools": ["mcp__claude_ai_Slack__search"],
 "needs_connectors": ["claude.ai Slack"], "output_schema": {},
 "session_id": "uuid", "persist_session": true, "space": "default",
 "append_system_prompt": "…", "partial": true, "account": null, "timeout_s": 900,
 "needs_you_when": {"pointer": "/status", "equals": "needs_you", "question_pointer": "/question"}}
```

- `kind` is a label, `^[a-z_]{1,32}$`, which rlxd records and echoes: task, widget_refresh, watch, check, send_executor, widget_author or parse_instruction.
- An empty `allowed_tools` means no tools.
- `needs_connectors` names the connectors that must be `connected` before the first turn (5.5). An empty list means none.
- `persist_session: false` makes a session-less run (`--no-session-persistence`), such as rlxapp's send-time `Check`. Its `session_id` is ignored, `run.done.session_id` is `null`, and `run.resume` refuses it with `no_session`.
- `needs_you_when` tells rlxd when a finished run is needs-you rather than done.

**The run's states:**
- `queued` → `running`;
- `running` → `done`, `failed` or `needs_you`;
- `needs_you` → a new run through `run.resume`;
- any state → `failed {reason: "cancelled"}` through `run.cancel`.

**Run events** (topic `run`). `call_id` is Claude Code's `tool_use_id`, so one call's `run.tool_call`, `run.tool_decided` and `run.tool_result` share it.

| Type | When | `data` |
|---|---|---|
| `run.queued` | over `max_concurrent_runs` | `run_id, job_id?, position` |
| `run.started` | stream-json `system/init`, once every connector in `needs_connectors` is `connected` (5.5) | `run_id, session_id, kind, job_id?, cwd, model, tools[], mcp_servers[{name,status}], claude_version, resumed_from?` |
| `run.text` | `assistant` text; partial chunks when `partial` | `run_id, text, partial` |
| `run.tool_call` | the PreToolUse hook (5.1); **the app must answer `run.decide`** | `run_id, call_id, tool, input, deadline_ms` |
| `run.tool_decided` | after the decision | `run_id, call_id, decision: allow\|deny, by: app\|rlxd\|timeout\|unreachable, reason` |
| `run.tool_result` | a `tool_result` block in a stream-json `user` message | `run_id, call_id, is_error, content, truncated`. `content` is the block's content exactly as Claude Code emitted it (a string or content blocks), up to 1 MiB; `truncated` says whether it was cut. rlxapp's condition triggers read `match.path` from it (rlxapp architecture §8.5) |
| `run.rate_limited` | `rate_limit_event` | `run_id, resets_at?` |
| `run.needs_you` | `needs_you_when` matched the final output | `run_id, session_id, reason: "question", question` |
| `run.done` | `result`, success | `run_id, session_id, result, structured_output?, usage{input_tokens,output_tokens}, cost_usd?, duration_ms, num_turns` |
| `run.failed` | error, timeout, cancel, engine restart, or a connector-gate miss (5.5) | `run_id, session_id, reason: cancelled\|error\|timeout\|auth\|rate_limited\|engine_restarted\|connectors, message, partial_text, connectors?[{id,status}]` |

**The commands:**

- `run.resume {run_id, reply}` returns `{run_id}`. The new run has the same session, and its `run.started` carries `resumed_from`.

### 7.6 Scheduler jobs and events `independent`

**`job.add` params.** It returns `{job_id}`:

```json
{"name": "Slack digest", "schedule": {"every_minutes": 15},
```

### 7.8 Install, upgrade and sign-in as JSON lines `needs 0.10.2: #568` (install), `independent` (upgrade), `needs 0.10.2: #564` (sign-in)
Every line is an event envelope (7.3) whose `seq` is local to the stream. stdout carries nothing else. Human text goes to stderr.

**Install** `needs 0.10.2: #568`.
- **Events:**

- **Accept:**

**Sign-in** `needs 0.10.2: #564`.
- **Events:**
  - `signin.open_url {url}`;
  - `signin.waiting {expires_at?}`;

- **Accept.** `RLXD_CLAUDE_BIN` points at the named fixture. Stdin is held open by `< <(sleep 60)` unless a check closes it:

  - **SIGTERM.** With `fake-claude/login-slow`, `rlx --schema-version 1 accounts add --json-lines < <(sleep 60) > si.jsonl & p=$!; sleep 2; kill -TERM "$p"; wait "$p"; echo $?` prints `1`, with the same last line.
  - **Timeout.** With `fake-claude/login-slow` and `--timeout 2`, the exit is 1, and `jq -s -e '.[-1].type == "signin.error" and .[-1].data.code == "timeout"' si.jsonl` exits 0.
